## Build
1. **`bh thread list|show|peek|summary [<id>] [--json]`**: an additive, derived Thread read model. One task = one thread (plans that became tasks merge into that thread; a plan not yet a task is its own thread). A thread holds: id, title, state (one of the 7 spec states: needsYou, review, working, done, failed, paused, idle; derived from open questions/blockers, QA gate, active agents, status), agents (names, for avatars), steps done/total, age, cost/tokens (for the peek, not the row), branch/worktree, and the parts for its 4 sub-tabs: Conversation (chat replies for the task), Plan, Steps, Changes (diff stat vs base). `peek` = recent output lines, any open question, and the reply target. `summary` = the one-line live summary from the deterministic 0-token summarizer (latest tool/activity/step/board entry). Rows are keyed by stable thread id. Never throws on corrupt or legacy data: skip the bad record with a calm fallback and a logged entry.
2. **`bh home [--json]`**: `needsYou` (open questions, blockers, QA reviews, held approvals, untriaged GitHub issues from the issues cache, ranked first), `review`, then `fleet` (running agents with state + one-line summary, running goals with progress), `spendToday`, and a header count like "3 running · 1 needs you" (correct plurals).
3. **`bh goal progress [<task>] [--json]`**: the goal row's data from the same source as `bh goal status --json`: goal title, gate reached (milestone/criteria passed of total), elapsed, retries left, the judge's last reason, paused or not. Also sync the task's `progress.md` checks table from it (single source of truth; preserve hand-written sections), via `bh goal progress --sync`.
4. **`install.mjs` layout migration**: the new 5-destination layout (Home, Threads, Agents with `Fleet | Terminals`, Library with `Knowledge | Learning | Scripts | Issues`, Settings gear including Usage) will land with the M4 UI. Keep it behind the layout file that ships: don't change `layouts/bot-herdr.json` yet (the UI Dev does that in M4 proper).
