## What to do
Element ids matter: the audit finds features by id prefix.
1. **Three-choice approval card** (`approvalcard.js`, ids `bh-approval-<id>`, buttons `bh-approval-<id>-once|project|deny`). Shows the agent avatar + name, the title, and the command as one folded mono machine line (Principle 6, reuse `machinetext.js`). Buttons: **Allow once** (the view's one primary), **Allow for this project**, **Deny** (both secondary; Deny is not a danger fill). Click runs `bh approvals answer <id> once|project|deny`; keys `1`/`2`/`3` while the card has focus. Draw it in the Peek when the peeked Home row is kind `approval` (`home.js:29`, `peek.js`), and in the thread's conversation top when a pending approval's `task` is this thread (`bh approvals list --json`, refreshed with the thread). After answering, the card folds over `MOTION.fold` like the answered question card.
2. **Diff review with inline comments** (`diffreview.js`, ids `bh-diff-<path>`, `bh-diff-line-<path>-<new>`, `bh-review-comment-<id>`, `bh-review-send`). In Threads › Changes (`threads.js:625-648`) a file row expands in place into its diff (`bh review diff`): one row per line, mono, add/del marked with `c.stateDone`/`c.stateFailed` text and a `+`/`−` gutter (never a fill), line numbers muted. Clicking a line or Enter on a focused line opens one inline input under it; Enter saves (`bh review add`), Esc cancels. Comments show under their line with Remove. A **Send to Dev · N** button (`bh-review-send`, hidden when N = 0, Principle 3) runs `bh review send`. Keep "Open diff" as is.
3. **Summary / Normal / Verbose** (`threads.js:482-501`, segmented control ids `bh-view-mode`, `bh-view-mode-summary|normal|verbose`, after the sub-tab strip). Normal is the default and is today's conversation (one-line collapsed cards). Summary: the thread's one-line summary, then only needs-you entries, decisions and done entries as one line each. Verbose: every entry expanded to its full text and machine text unfolded. Keep the mode per thread in memory; `v` cycles it while the thread view has focus and no input is typing. Add it to `keymap.js`.
4. **Child threads and a thread map** (`threadmap.js`, ids `bh-thread-map`, `bh-thread-map-<name|id>`). Replace the "N child reports" line with a tree under the thread header: the parent, its `children` (avatar + name, state glyph, step), and `forks` (title, state) as one-line rows; a row opens its peek on Space and its thread/terminal on Enter. Hidden when there are no children and no forks. Show "Forked from <title>" (muted, clickable) when `forkOf` is set.
5. **Handoff and fork** (ids `bh-thread-fork`, `bh-fork-input`). A **Fork** secondary action in the thread header opens an inline input prefilled with the thread's summary line; Enter runs `bh thread fork <id> "<text>"` and opens the new thread.
6. **Queue and steer** (`composer.js`, ids `bh-queue-<n>`, `bh-steer`). While the target agent is working, Enter queues: the message shows as a muted row above the composer ("Queued", with Remove while it has not been delivered) and is sent with `hc send`; **Ctrl+Enter** steers (`hc interrupt <agent>` then `hc send`), labelled in the placeholder at `composer.js:1635`. Under no agent working, Enter sends as today.
7. **Tiled agent panes** (`agents.js`, `layouts/bot-herdr.json:182-235`, ids `bh-agents-tile`). In the Agents › Terminals strip, a **Tile** toggle shows two or more agents' terminals side by side. First read `~/.config/herdr-app/AGENTS.md` (Layouts, panes, `pane.split`) and `~/.config/herdr-app/herdr.d.ts` for an API that puts an existing terminal beside the active one (a `{ "terminal": "<addr>" }` block, a split, or a move). Use the one that exists; if none can show an existing agent's terminal beside another, stop this item and report it as a blocker with what you checked.
8. **Tests** (`test/m6-ui.test.mjs`): pure helpers for each item (approval button → command args, diff row model and line ids, view-mode filtering of entries, thread-map tree from `children`/`forks`, queue/steer command choice).
